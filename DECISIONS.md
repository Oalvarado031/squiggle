# Decisions

Numbered so code and commits can point at them. Newest last.

**1. Layout.** npm workspaces: `packages/core` (squiggle-core: lexer, parser, interpreter, renderers, tidy/squeeze, share links, vocabulary), `packages/cli` (the `squigglelang` npm package), `packages/vscode`, `site` (Cloudflare Worker + Vite client), `action/squiggle-render`, `examples/` (30 starters), `seeds/` (12 wall seeds). Core is TypeScript with no dependencies and is imported directly by the site, the Worker and the CLI bundle, so the studio, the CLI and the server run the same interpreter.

**2. The interpreter draws into a display list, not onto a canvas.** A frame is a flat list of ops (`dot`, `ring`, `box`, `line`, `path`, `shape`, `text`, `paper`) with a transform each. Two renderers consume it: Canvas2D (browser, OffscreenCanvas in a Web Worker, and `@napi-rs/canvas` in the CLI, all through the same `drawFrame`) and SVG (the Worker rasterizes it with resvg-wasm, since Workers have no canvas). Frame hashes are computed from the display list, so the determinism test doesn't depend on any rasterizer.

**3. A frame is a pure function of t.** Lines outside `every frame` run once; what they draw stays on the sheet as the bottom layer, and the values they store are where each frame starts. Every frame starts from a copy of those values, with `rand` restarted from the piece's seed. So scrubbing, exporting, the wall preview and the OG card always agree for any t, in any order. Only `when` blocks (input) change values that persist; they can't draw (they'd have nowhere to draw). Several `every frame` blocks run in order.

**4. rand starts from seed 1 for every piece, not from a hash of the code.** The spec asks that the same code always gives the same art; seeding from the code hash would also do that, but every keystroke in the studio (even in a comment) would reshuffle the whole piece. A fixed starting seed keeps the art steady while you edit; `seed n` picks another. `noise` uses a fixed permutation table.

**5. Determinism across engines.** Every coordinate and size in the display list is snapped to 1/256 px and every matrix entry to 1/65536 before drawing or hashing, so last-bit differences in `Math.sin`/`cos` between JavaScript engines can't change pixels or hashes. Randomness is sfc32 seeded through an integer hash; colors are integer RGB with alpha rounded to 1/1000.

**6. Budgets are counted in steps, not milliseconds.** Every statement and expression evaluation is one step. A frame (and each `when` run) may take 250,000 steps and draw 20,000 shapes; the lines outside `every frame` get 1,000,000 steps. Lists cap at 10,000 items, text at 2,000 chars, `make` nesting at 64, paths at 5,000 points, a piece at 20,000 chars. Steps rather than time because Cloudflare Workers freeze the clock during CPU work, and because a step budget gives the same verdict on every machine: a piece that runs in the studio runs on the server. The budget error names the innermost loop that was running.

**7. Small language choices.** Comments are `//` (`#` is taken by colors). `repeat n` without `as` names its counter `i` (a golf trick and less typing for beginners; nested repeats get their own `i`). Commands also accept `dot(1, 2, 3)`. Anywhere two numbers form x, y a point works. `%` is floored (always positive for positive divisors). `box` is centered on x, y. `dot`'s size is its radius. `keep` restores color and width as well as the transform. `make` blocks are hoisted. New names inside `make` are local; existing top-level names are shared. `paper`, `ember`, `sin` and other built-in names can't be reassigned (clear errors instead of confusing shadowing). Added beyond the spec: `shape` (filled polygon), `seed`, `say`, `pick`, `range`, `polar`, `dist`, `fade`, `rgb`, `atan`, `pi`, `mouse`, `tan`, `ceil`, `round`, `sign`, `min`, `max`, `sqrt`.

**8. Errors.** Parsing stops at the first problem. Every error carries line, column, an underline length, a plain message and, when there's a likely fix, a `try:` line. Unknown names get "did you mean" suggestions (edit distance with transpositions) and words from other tools (`circle`, `rect`, `rotate`, `background`…) map to Squiggle's names. Non-finite numbers skip the shape and leave a note instead of crashing.

**9. Post length counts like X.** The meter and "fits in a post" use X's weighting (most Latin text and punctuation 1, CJK and emoji 2) on the code with trailing spaces and blank edge lines removed. A post with the code and a link needs code ≤ 256 (X counts every link as 23 plus a newline).

**10. Share links carry the code.** `deflate-raw` + base64url in `/studio?c=…`. No server state; the Worker can still render an OG card for any share link because the code is in the URL.

**11. tidy and squeeze work on tokens after a full parse.** tidy keeps comments and single blank lines. squeeze removes comments and spaces, shortens numbers (`0.30` → `.3`), colors (`#15130f` → `ink`, `#ff0000` → `#f00`), renames long names to free short ones (never to `i`, `t` or a built-in), and drops `as i`. The squeezed code is accepted only if its frame hashes at five times (and its `say` output) match the original; otherwise it falls back step by step.

**12. Text in pieces uses Fraunces Regular**, the same static TTF in the browser worker, the CLI and the server renderer, so `write` looks the same everywhere.

**13. CLI stack.** `@napi-rs/canvas` (prebuilt for macOS, Linux, Windows, so `npx` needs no build tools), `gifenc` (bundled) for GIF, `h264-mp4-encoder` (WASM) for MP4. Clips render offline at a fixed fps (`t = frame / fps`), so the same command gives the same file. A starter name works wherever a file path does (`squiggle render tide`).

**14. Small language changes after the starters were written.** A negative size draws nothing (it used to be flipped positive, so a shrinking ripple came back). `true` and `false` count as 1 and 0 in arithmetic (`(i % 2 == 0) * 20`). When a `make` reads a name that only exists in the lines that called it (a loop counter, usually), the error says so and shows how to pass it in. None of the 42 pieces' frame hashes changed.

**15. One Worker serves everything.** Static pages are built by Vite; the Worker runs first on every request (`run_worker_first`) and fills in what changes with HTMLRewriter: the weekly theme, the CA chip (`TOKEN_MINT`), config links, and for `/p/<id>` the title, description, OG image and the piece's JSON. `/studio?c=…` gets an OG card of the code in the link. CSP allows only same-origin scripts plus the hash of the one inline script (theme before paint); styles allow inline because CodeMirror injects them.

**16. User code runs only in Web Workers.** One worker per page owns every interpreter and draws into OffscreenCanvases. Before any piece runs, `fetch`, `XMLHttpRequest`, `WebSocket`, `importScripts`, `indexedDB`, `caches` and friends are removed from the worker (the language can't reach JavaScript anyway). Squeeze and the learn goal checks also execute code, so they run there as jobs. Without OffscreenCanvas the worker still runs the code and the page only draws the display list. A watchdog restarts the worker if it stops answering for 6 s.

**17. The wall never runs anyone's code.** Pinning renders a still (t = 1) and a 3-second preview sprite on the server: 45 frames at 15 fps, 320 px each in a 9-column grid, or fewer frames (down to 12) for pieces with many shapes (150,000 shapes across the preview at most), and at most 6,000,000 steps. Cards show the still and step through the sprite while on screen. The piece page runs the code live.

**18. Pinning limits.** Code up to 2,000 characters (pieces over 280 can be pinned; they just don't get the stamp), title up to 60, an optional X handle (`[A-Za-z0-9_]{1,15}`, shown as text; `squiggle` is reserved for the seed script's admin token). Six pins an hour and 30 a day per network. The same code from the same network within 10 minutes returns the existing piece. A word filter reads the title, the handle, and every string and comment in the code.

**19. Likes.** One per browser (a random 24-character id in localStorage) and at most three per network on one piece (NAT-friendly), plus 240 likes an hour per network (KV counter). Networks are identified by `sha256(IP_SALT | ip)`; raw IPs are never stored.

**20. "Top today" and "top week"** rank by likes received in the window, so an older piece can climb back; pieces pinned in the window are listed even with no likes yet.

**21. Weekly prompt.** Weeks run Monday to Monday (UTC, ISO week ids). The rotation starts with "weather" on 2026-W44; a row in `prompts` overrides any week. A Monday cron freezes last week's top three entries by likes (also done lazily if the cron missed), and their pages get a stamp ("1st · weather · week 44").

**22. OG cards** are 1200 × 630: the piece at t = 1 on a taped sheet, the title, the handle, the count and the stamp, composed as SVG and rasterized with resvg, cached in R2. Share-link cards are cached by code hash and rendered at most 60 an hour per network.

**23. Post on X** puts the code itself in the post when the code, a newline and the link (23) fit in 280; otherwise the title, the count and the link.

**24. Performance.** Each page's CSS (about 15 KB) is inlined. The studio prints its first-visit piece (orbit-garden) into the HTML as plain text in a system monospace font; it is the largest paint, and CodeMirror replaces it once fonts are ready. Fonts are self-hosted with `font-display: swap`; only JetBrains Mono is preloaded, on pages that show code.

**25. Exports** come from a fresh interpreter (clicks and keys pressed so far don't leak in): PNG at 1024 px, and 6-second clips at 30 fps as MP4 (WebCodecs H.264 through mp4-muxer) or, where the browser can't encode H.264, GIF at 20 fps.

**26. Launch assets are drawn, not screen-recorded.** `npm run record` draws the 20-second clip frame by frame with the real interpreter and the real OG card renderer, then encodes vertical and horizontal MP4s with ffmpeg; `npm run hero-gif` makes the README GIF. Re-running gives the same video.

**27. Production.** Cloudflare account `oiaj2341@gmail.com` (the one that hosts the other launches), Worker `squiggle` at https://squiggle.oiaj2341.workers.dev, D1 `squiggle`, R2 `squiggle-media`, KV `squiggle`. Resource ids live in `site/wrangler.jsonc` (they aren't secrets); `IP_SALT` and `ADMIN_TOKEN` are Worker secrets, and the admin token is also in `.admin-token` (gitignored) for the seed script. Pins made with the admin token are stored with the network `admin`, so seeding never uses up anyone's six pins an hour. `scripts/deploy.mjs` and `scripts/seed.mjs` can be re-run safely.

**28. The stamp uses the deeper ember** (`--ember-deep`) for its small uppercase text: the bright ember on paper was 3.2:1, under the 4.5:1 that small text needs. The bright ember stays for large marks and the OG card.

**29. squigglee.online is the address.** Bought through Cloudflare Registrar in the same account; both the apex and `www` are Worker custom domains. `www` always redirects to the apex; with `CANONICAL_HOST` set, so does the workers.dev address, except `/api/` so old clients keep working. Share links, OG tags, the CLI's `link`, the extension's default studio URL, the install scripts and the launch videos use the new address. The CSP allows Cloudflare's cookie-free Web Analytics beacon, which Cloudflare injects on the custom domain.

**30. Cloudflare's analytics beacon is allowed, not blocked** (v1.0.1). The custom domain gets Cloudflare Web Analytics injected; the beacon script loads from `static.cloudflareinsights.com` and reports to `cloudflareinsights.com`. Both are in the CSP (`script-src` and `connect-src`), so pages have zero console errors. To drop it, turn Web Analytics off in the Cloudflare dashboard; the CSP entries can then go.

**31. Links live in one file** (v1.0.1). `squiggle.config.json` holds `siteUrl`, `repoUrl`, `xUrl`, `authorName` and `authorUrl`. `npm run sync-config` writes them into the Worker's vars (`REPO_URL`, `X_URL`, `AUTHOR_NAME`, `AUTHOR_URL`, `CANONICAL_HOST`), `SITE_URL` in core (used by the CLI and the extension), the CLI and extension manifests (`homepage`, `repository`, `bugs`, `author`), and the `<!-- sync:… -->` blocks in the READMEs. Pages ship those links without a URL and `hidden`; the Worker fills them in, or removes them when the value is empty, so an unset X account or repository shows nothing rather than a guess. CI runs `sync-config --check` and `scripts/check-links.mjs`, which fails if any tracked file, built page, bundle or the `.vsix` links to a Squiggle repository other than `repoUrl`. The footer's CLI link goes to the home page's "Take it with you" block instead of the repository.

**32. House pieces are credited to Squiggle, not to an X handle** (v1.0.1). The seeds were pinned as "@squiggle", which linked to x.com/squiggle, an account we don't own. Pieces pinned with the admin token are now house pieces (`house = 1`, no handle; migration 0002 converted the seeds). They read "by squiggle" on cards, piece pages and OG cards, and link to `X_URL` only when one is configured. A handle links to x.com only when a person typed it while pinning, and `squiggle` stays reserved so nobody else can use it. OG cards moved to a new cache key so the old "@squiggle" cards are redrawn.

**33. Prompts open with house entries** (v1.0.1). "This week: weather" showed "No entries yet". `prompts/<week>/*.sqg` holds house pieces for a week's theme (three for 2026-W44: downpour, lightning, morning fog, each under 256 characters so a post can carry the code and the link); `scripts/seed-prompt.mjs <url> <week>` pins them with the admin token, which may name the week. They're in the determinism snapshot like the starters. House pieces open a prompt but never take its top-three stamps. The rotation itself is unchanged and now has tests past the first week: a new theme every Monday (UTC), the list wraps after 20 themes, and the prompt tab lists only the current week's entries.

**34. "Post on X" carries the code** (v1.0.1). One helper in core, `postIntent`, builds the intent for both the piece page and the studio. When the code, a newline and the link (X counts any link as 23) fit in 280, the post text is the code followed by the link on its own line; the link goes inside the text rather than X's `url` parameter so it always lands under the code. Otherwise the text stays "title: N characters of Squiggle" plus the link. Pinning in the studio now ends on a "pinned" view in the dialog (Post on X, Open its page, Copy link) instead of jumping straight to the piece page. Paper boat (276 characters) still uses the title text: with the link it would need 300.

**35. squigglelang publishes from GitHub Actions with provenance** (v1.0.1). `publish squigglelang` (manual run, or a `cli-v*` tag) runs the tests, builds, writes the publishing repository into the package's `repository` field (so provenance checks out whichever account owns the repo), runs `npm publish --provenance --access public` with the `NPM_TOKEN` secret, then runs `npx squigglelang@<version> render examples/tide.sqg --out tide.png` on Linux, macOS and Windows. A daily `npx squigglelang smoke test` repeats that check once the package exists. Until npm has it, the home page's "Take it with you" block says "CLI coming soon": the Worker asks the registry (cached 10 minutes in KV), so the command appears by itself after the first publish, with no deploy. The install scripts say the package isn't published yet instead of failing inside npm.
